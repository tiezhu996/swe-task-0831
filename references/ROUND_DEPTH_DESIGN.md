# 出题深度与题面写法

平台只收有效轮数 >100 的完成样本，TraeCN 又贵，超出太多也是浪费。2026-10-30 起目标是 **TraeCN 110 到 200 轮**（用户定的可接受范围是 100 到 200）：下限留 10 轮余量（5128 正好 100 轮，不算过）；超过 200 轮上下文太长，平台也不多给钱。轮数来自模型实际做了多少事，不来自题面写了多少字。这份文档在选项目、定需求、写题面、本地试跑和执行后校准五个阶段使用，配套脚本：`check_prompt_rubric_scope.py` 的 `depth`/`effect` 检查、`check_prompt_style.py` 的文风检查、`trial_run.py` 的便宜模型试跑、`trajectory_metrics.py` 的轨迹度量。

## 2. 选项目

优先：

- 全栈项目（后端 + 前端页面，需求要同时改两侧）；
- 有两个以上存储后端或驱动，且新状态必须在各后端一致（SQLite/Redis、MySQL/PostgreSQL）；
- 多节点、复制或集群项目；
- 领域对象多、规则互相牵连的业务项目（记账、库存、权限、计费）。

避开：

- 单进程小代理、单一功能的工具；在这类项目上出题，大部分需求只有一个接入点；
- 验收依赖硬件（电视、投屏设备、GPU）、外部模型下载或云账号的项目；模型在本机跑不通就会写说明收尾（3370 只有 11 轮）；
- 基线本机构建不过或大面积测试失败的项目；3380 的基线 `db` 包编译不过，模型直接以“预存问题”结束。

选定后用 `scripts/screen_project.py --run-container` 在断网容器里跑基线构建和全量测试，报告里的 `baseline_health` 直接抄进 `depth.baseline_health`。门禁和阈值见 [PROJECT_SELECTION.md](PROJECT_SELECTION.md)。

## 3. 设计改动处和停止陷阱

不要靠加功能把题变大。深度来自把一个简单诉求落到这份基线上时，必然要碰到的那些地方。出题人在固定基线上做两件事。

**数改动处。** 把诉求落到源码，用 `git grep`、gopls references 或调用图找出实现它必须修改的位置：每个入口、每个数据流出或写入点、每个缓存和持久化路径。按“相对路径:行号”记下来，每处写一句为什么非改不可。至少 12 处、分布在至少 4 个文件；也不能超过 30 处或 10 个文件，超了是题出大了而不是出深了，收窄范围或拆成两道。改动集中在一个新模块里的需求（日志、统计、监控、配置开关、单个中间件、单入口批量操作）凑不够，直接换题。

**找停止陷阱。** 停止陷阱是一个“看起来做完了、其实没做完”的实现，只有在本地实际跑一次才能发现。模型会在这里继续改，形成改-跑-改循环；没有陷阱，模型写完就收尾。每个陷阱写明：

- `looks_done`：哪种实现看起来已经完成；
- `exposed_by`：怎样在本机离线把它跑出错，例如用 `httptest` 假上游、本地 `registry:2`、`curl` 下到一半 kill；
- `clause_ids`：对应题面哪一句。陷阱必须由题面里的诉求产生，不能题面不提、验收时才冒出来。

至少 2 个陷阱，都要能本地跑出来（`local=true`）。需要联网、硬件或外部模型下载才能暴露的不算。

**登记预测。** 执行前写下预测的轮数区间，下限不低于 100。final 阶段校验器会把实际轮数和预测区间放进 `round_prediction`，不阻断提交，只用来校准第 4 节的阈值。

### 例子：hubproxy 配额题

> 只作为数改动处和找陷阱的演示，不能直接出题：hubproxy 过不了 [选项目门禁](PROJECT_SELECTION.md)（非测试源码只有 11 个文件），而且“拉镜像前先登录”和一个未合并的公开 PR（Web 登录 + 拉镜像 JWT 认证，840 行）功能重合，按功能重合门禁要换掉登录这一半。

基线 77ece22 上，“每人一个账号、按月扣流量”这个诉求必然碰到的位置：

- 身份：拉镜像走 `/token` 加 `/v2` 认证流程（`src/main.go:110-112`），GitHub 走 `NoRoute` 转发（`src/main.go:113`），离线包走 `/api/image`（`src/handlers/imagetar.go:710-715`），三处拿身份的方式不同；
- 字节流出：`docker.go` 3 处、`github.go` 2 处 `io.Copy`，`imagetar.go` 6 处 `tarWriter.Write`/`io.Copy`；
- 缓存：manifest 缓存命中时由 `c.Data` 从内存返回（`docker.go:234`、`docker.go:560`、`utils/cache.go:128`），token 缓存 key 只取查询串（`docker.go:314`）；
- 持久化：基线没有，要新加。

停止陷阱：只在 `io.Copy` 后按 Content-Length 记账，`curl` 下到一半 kill 就会多扣；只统计上游转发，第二次拉同一镜像命中缓存时漏扣；按原样复用 token 缓存，甲先拉、乙再拉同一镜像时流量记到甲头上。

## 4. depth 合同

写在 `design-contract.json` 顶层，和 `prompt_clauses` 平级：

```json
"depth": {
  "edit_sites": [
    {"location": "src/handlers/docker.go:274", "reason": "镜像层字节在这里流出，要按实际写出的字节记账"},
    {"location": "src/handlers/docker.go:314", "reason": "token 缓存 key 不含用户，两个人会共用凭证"}
  ],
  "stop_traps": [
    {
      "clause_ids": ["P3"],
      "looks_done": "io.Copy 结束后按 Content-Length 扣额度",
      "exposed_by": "httptest 假上游加 curl 下到一半 kill，比较 size_download 和已扣流量",
      "local": true
    }
  ],
  "predicted_rounds": {"low": 110, "high": 180},
  "baseline_health": {
    "build": "pass",
    "tests": "pass",
    "known_failures": [],
    "external_deps": [],
    "evidence": [{"path": "/绝对路径/baseline-test.log", "sha256": "...", "bytes": 1234}]
  }
}
```

（示例只列了部分改动处和陷阱，实际合同要达到下面的数量。）

同样在顶层写 `effect`，登记效果落点（2026-10-30 起 design 阶段必填，写法见第 5 节）：

```json
"effect": {
  "seen_in": ["现有的扫描命令输出"],
  "quote": "扫完在原来的结果里多列一栏就行，不用另做报告",
  "allowed_new": []
}
```

- `seen_in`：用户在哪个**现有**功能、命令或页面上看到结果。
- `quote`：逐字摘自题面，交代效果落点的那句话。校验器要求它在题面原文里，只写进合同不算。
- `allowed_new`：这道题允许新增的入口类型，取值 `page`、`endpoint`、`command`、`setting`；不新增写空列表。全栈题要做新页面就写 `page`，题面里也要说出来。

运行时加 `--source /绝对路径/sources/<任务>`，校验器会核对每个改动处的文件确实存在于基线、行号在文件范围内。

规则：

- `submission.phase=design` 时必须有 `depth`，并且 Rubric 至少 8 条。下列任一情况非零退出：改动处少于 12 个或少于 4 个文件；有效停止陷阱少于 2 个；陷阱不能本地跑出；预测下限低于 100；`external_deps` 非空；基线构建不过。
- 阈值是 2026-10-26 按 10 个会话定的临时值：过 100 轮的会话 Edit 都在 10 次以上。新任务执行后用 `trajectory_metrics.py` 量一次，和预测区间一起补进第 1 节，命中率低就调阈值。
- `tests=known_failures` 时逐项列出失败的既有测试，并确认它们和本题无关。
- 2026-10-26 前的旧合同没有 `depth`，到 final 阶段不补；填了就照样校验。
- 改动处和陷阱只留在本地合同里，不能写进题面，也不能放进模型工作区。
- `predicted_rounds` 填第 6 节试跑换算出的区间（`trial-run.json` 的 `prediction.band`），不再由出题模型自己估。还没有校准文件时可以先估，但预检门禁的 `trial` 一项过不了。

## 5. 题面写法

题面是同事在群里描述自己碰到的麻烦。写之前先回答：谁在用什么数据，做了哪几步，结果哪里不对，现在怎么凑合。

**允许并鼓励**：

- 项目里的产品名词和真实操作：拉镜像、GitHub Release、Redis 后端、信用卡还款、洞察图表。产品名和用户能看到的操作不算代码术语；文件名、函数名、配置键、类名仍然不能出现。
- `runtime/tools/validate_hard_task.py`（A/B 审阅用）会拒绝 API、JSON、HTTP、HTTPS、SQL、Go、Docker、commit、token、endpoint、schema、CLI、SDK 这些词和任何斜杠，题面里换成“拉镜像”“令牌”“接口”等说法。
- 具体的数字和后果：差了几百块、月底流量超了、第一条请求就报错。
- 口语化的连接：得、又、也、结果、后来、现在只能。

**改掉**：

| 写法 | 问题 | 改成 |
|---|---|---|
| 一句痛点。希望能 X。（空行）……的时候，……不能受影响。 | 固定模板；第二段是给 Rubric 留的钩子 | 把约束放进场景：“我调了谁的额度要马上生效” |
| 退款、转账、账户间还款和缺失凭证要明确区分 | 把 Rubric 压成顿号清单 | 写症状：“退款被算成了收入，信用卡还款又被当成支出算了一遍” |
| 有些数据、一些设置、上游 | 不点名对象，放到哪个项目都成立 | 点名：临时导入的测试库、黑白名单和限流额度 |
| 可复核、形成明确版本、平滑、干净关闭、互相串、不受影响 | 书面规格腔 | 写用户能看到的结果：“每个数字点进去能看到是哪些流水” |
| 希望……希望……希望…… | 每个诉求同一个开头 | 只在需要时用一次“想要”或“希望” |

**说清效果落在哪，做到哪为止**（2026-10-30 起）。TraeCN 动手前会二次确认，问要不要实现对应的接口、页面和测试。题面只说麻烦、不说结果在哪看到，确认时它就会把接口、管理页面和关联业务都列进计划，标注的人一点确认，需求就膨胀了，轮数也跟着失控。题面里要用一句同事口吻的话把这个问题提前答掉：

- 点名用户在哪个现有功能上看到结果：“扫完在原来的结果里多列一栏就行”“就在洞察页原来那个图上加个存档按钮”“查询那一层能停下来就够了，报表服务那边我们自己接”。
- 顺口说一句这次不碰什么，用“就行”“就够了”“先不用”“我们自己来”这类说法：“权限先在代码里配，不用做管理界面”。不要写“不得新增页面”“范围仅限于”“无需实现接口”这类条款。
- 测试也是确认时会问的一项。想让模型补测试，就顺口说“顺手补几条测试”；不说的话，试跑和 TraeCN 各自决定，轮数波动会变大。
- 这句话就是合同里 `effect.quote` 的来源。它最多占一句，不要为了堵 TraeCN 的问题把题面写成范围说明书。

写完用 `trial_run.py confirm` 预演一次二次确认（第 6 节）：只给便宜模型看题面，让它列出打算新增的页面、接口、命令、配置和想先问的问题。列出了 `effect.allowed_new` 之外的东西，就回来改这句话。

**Rubric 锚点放在症状句里**。范围合同的 `quote` 逐字取自题面，症状句一样能当锚点：“信用卡还款和账户之间转钱又不能算进去”可以同时支撑“还款不计入支出”和“转账不计入支出”两条 Rubric。不需要为了回指把名词列成清单。

**长度**：预检上限 240 字。三类以上信号的题通常需要 130 到 220 字；只有一两句话的题面难以承载 8 条 Rubric。

### 改写示例

1527 原题（238 轮，内容不变）：

> 每年报税时，我都要把一年的支出重新筛一遍。可抵扣的分类、退款冲减、跨币种折算和没有票据的项目现在只能导出后手工算，金额对不上时也不知道具体来自哪些流水。希望能生成一份可复核的年度税务汇总，按选定年度展示每一类金额的计算口径和来源交易，跨币种使用交易日汇率，退款、转账、账户间还款和缺失凭证要明确区分；我补充凭证或调整归类后，汇总能重新计算并保留前后差异。

改写后（179 字）：

> 每年报税我都得把一年的支出导出来重新算。能抵扣的分类要单独加，退款得从原来那笔里扣掉，美元日元的消费要按当天汇率折回人民币，信用卡还款和账户之间转钱又不能算进去。最后总数跟我手算的差几百块，也查不出差在哪几笔。想要一份按年出的税务汇总，每个数字点进去能看到是哪些流水算出来的，没票据的单独列出来。后面补了票据或者改了分类，重新出一次时能看出跟上次比哪里变了。

hubproxy 换题型（165 字，2026-10-26 按基线 77ece22 源码改写；文风演示，功能重合见第 3 节例子的说明）：

> 团队共用这台加速服务，月底流量超了也不知道是谁拉的。想让每个人用自己的账号：拉镜像前先登录，下 GitHub 文件和打离线包也带上自己的账号，三种用法扣同一份月度额度。扣的是真正传到对方手里的量，命中缓存的也算，中途断开的只算已经传完的部分；甲登录后拿到的凭证，乙不能蹭着用。超了就拒掉，告诉对方几号恢复，服务重启后已用量不清零。

难点都来自基线源码，题面没有额外加功能：三个入口传身份的方式各不相同（拉镜像走 `/token` 加 `/v2` 认证流程，GitHub 走 `NoRoute` 转发，离线包走 `/api/image`）；字节在 11 处 `io.Copy`/`tarWriter.Write` 流出，manifest 缓存命中时由 `c.Data` 从内存返回；token 缓存的 key 只取查询串，按原样会让两个人共用同一份凭证；基线完全没有持久化。

## 6. 本地试跑（2026-10-30 起，预检前必做）

静态门禁只能说明题面合规，说明不了 TraeCN 会跑多少轮。题面过了文本独立、功能重合、文风、范围与深度四道门禁后，先用便宜模型在同一基线上实际跑，判断落不落在窗口里，再发平台预检。试错的钱花在便宜模型上，TraeCN 只跑已经验证过的题面。

```bash
S=~/.codex/skills/swe-task/scripts
# 1. 预演二次确认：只读，看模型打算新增哪些页面、接口、命令、配置，开工前想问什么
python3 $S/trial_run.py confirm --source <基线源码树> --commit <基线 commit> \
  --prompt <任务目录>/PROMPT.md --contract <任务目录>/design-contract.json \
  --out-dir ~/repositories/标注任务/swe/trials/<编号>-<项目>
# 2. 完整试跑（默认自适应：先跑一次，改动源码文件在 11-17 个之间才跑第二次），换算成 TraeCN 轮数
python3 $S/trial_run.py run --source <基线源码树> --commit <基线 commit> \
  --prompt <任务目录>/PROMPT.md --contract <任务目录>/design-contract.json \
  --out-dir ~/repositories/标注任务/swe/trials/<编号>-<项目> --runs 2
```

- 后端默认是 Claude Code 接 DeepSeek（`~/.config/deepseek.env`，模型 `deepseek-flash`），可用 `--env-file`/`--model` 换。每次试跑用独立的 `CLAUDE_CONFIG_DIR`，不带本机的全局 CLAUDE.md、钩子、技能和记忆；禁用联网搜索和子代理，免得模型去翻上游 PR。
- 每次试跑用 `git archive` 从基线导出到 `~/.cache/swe-trial-ws/<随机名>/`，路径里没有题号和项目名，只有一个提交信息为 `init` 的提交，看不到上游历史。结果写在 `trials/` 下，脚本拒绝写进 `sources/` 或 `workflow/`。试跑的代码、日志和结论**不得**进入 Trae 工作区，也不能给执行者看。
- 模型进程跑在 `sandbox-exec` 里：读写 `~/repositories`、`~/.codex`、`~/.claude`、`~/Documents`、`/private/tmp`、`/private/var/folders` 和其他试跑目录一律拒绝，只放开本次试跑自己的目录；`TMPDIR` 和 Claude Code 的临时目录都指向本次试跑目录。出网走一个不通的代理，只放行模型后端和 PyPI、Go、npm 等包仓库，GitHub 访问不到。事件日志里的接口密钥会被替换成 `<redacted>`。
- 这些限制来自 2026-10-30 的两次实测：没加沙箱时，模型从工作区往上翻进 `sources/5130-rdflib`，直接读到了 Trae 的答案；加了沙箱、但没管 `/tmp` 时，模型又去翻 `/tmp` 里上一次试跑留下的测试覆盖率文件，还拿日志里的基线提交号去 GitHub 查。便宜模型很容易把题当成“有标准答案的考题”去找答案，隔离做不严，试跑出来的轮数就不可信。
- 熔断有两条，任何档位都拦：两次试跑改动的源码文件（不含测试和文档）中位数 ≥14 个，判“铺得太大”；单次工具调用超过 400 次（`--max-tool-calls`）就停，判“太大”，这条只管成本，21 道已执行题单次最多 356 次。deepseek-flash 爱拆小 Bash，每分钟 15-20 次工具调用，不要用 Trae 的经验去设这个数（10-30 起初设 150，6 分钟就快被 Trae 只有 56 轮的 5130 碰到）。超时（默认 75 分钟）和后端报错（如余额不足返回 402，记 `api_error`）判“无结论”，先看 `stderr.log`。驱动进程崩了但模型跑完的，用 `run --recover` 从事件日志和留下的工作区补算，不必重跑。
- 自适应试跑：同一题两次试跑的改动源码文件最多差 7 个（5127：4 对 11），第一次 ≤10 或 ≥18 个时第二次改不了铺开熔断的结论，就省掉第二次；11-17 个才跑第二次。按 21 道已执行题回放，18 道只需跑一次（需要第二次的只有 3378、5108、1527），熔断结论一道都没变，试跑总量省约 43%。`--no-adaptive` 强制两次。`check` 只在第一次落在 ≤10 或 ≥18 时接受单次结果。
- 停止陷阱评审：试跑结束后，用同一个便宜模型读压缩后的轨迹（每步命令、改动片段、失败输出），对合同里每个停止陷阱判一个状态，写进 `run-*/trap-judgement.json`：`hit_then_fixed`（先停在“看起来做完了”，跑测试或自查后返工，这才是陷阱该带来的轮数）、`fixed_upfront`（一上来就做对了）、`missed`（到最后都没发现）、`unclear`。汇总在 `trial-run.json` 的 `stop_traps`。没有一个陷阱出现 `hit_then_fixed` 时提示陷阱太浅；某个陷阱每次都是 `missed` 时提示 TraeCN 可能停在半成品。只提示不拦。10-30 在 9 道有合同的已执行题上回放：`hit_then_fixed` 的比例和 TraeCN 轮数无关（<100 轮的 5 道 58%，≥100 轮的 4 道 55%，56 轮的 5130 四次全是 `hit_then_fixed`），便宜模型会掉进去的陷阱 TraeCN 不一定掉；“陷阱太浅”提示 2 次都落在 <100 轮的题上（5123、5126），≥100 轮的题没有误报，但 5 道 <100 轮的题只抓到 2 道。所以只信这条提示，别拿 `hit_then_fixed` 次数当轮数依据。评审默认开思考，拿不到正文（回放时 16 次里有 7 次思考吃光了额度）就关思考重试一次。`--no-trap-judge` 关掉。
- 换算：`trials/calibration.json` 由 `trial_run.py calibrate` 拟合，用的是已执行任务的真实 TraeCN 轮数和同题面的试跑指标，带留一法误差。`trial_run.py run` 开跑前会检查：有试跑结果或 `task-state.json` 比校准文件新，就自动重新校准，所以每道题照流程先试跑、再执行、回填轮数，下一次试跑就会用上它。校准文件的 `executed_without_trial` 列出 Trae 已执行但没试跑过的题，可以用 `trials/run_calibration.sh` 补跑。
- 判定写在 `trial-run.json` 的 `verdict`：熔断给出的 `too_large` 必须先缩小需求；换算给出的 `too_small`/`too_large` 在 `breaker_only` 档只是提示，结合同项目已执行题的试跑指标判断（见下面的校准结果）；`off_contract_source_files` 非空说明模型改了必改位置以外的源码，对照 `confirm` 的结果改题面那句效果落点。
- `precheck_gate.py` 的第五道门禁 `trial` 只读这两份结果：都要绑定当前题面哈希，`run` 至少两次正常结束，`confirm` 没有 errors。门禁有多硬，看校准的三档判对率（`calibration.json` 的 `gate_mode`，2026-10-30 用户认可的分层方案）：判对率 ≥80% 是 `hard`，不在窗口就拦；60-80% 是 `advisory`，只有换算区间整段低于 100 或整段高于窗口上限才拦，其余写进 warnings；<60% 或还没校准是 `breaker_only`，轮数换算只提示。三档都会拦熔断、超时和 `confirm` 的 errors。题面改过一个字都要重新试跑。

## 7. 执行后取证与校准

Trae 会轮转 renderer.log，几天后原始事件就没了。采集 Session 后立刻归档：

```bash
python scripts/trajectory_metrics.py --workspace /绝对路径/sources/<任务> \
  --archive-dir /绝对路径/workflow/<任务>/trajectories/archive
```

它把本会话的日志行写进 `trae-renderer-session.private.log`，把度量写进 `trajectory-metrics.json`，权限都是 0600；文件已存在且内容不同就拒绝覆盖。有效轮数仍以 `capture_trae_session.py` 的核验结果为准，这里只是诊断。

`capture_trae_session.py --update-rounds --apply` 回填真实轮数后，校准会在下一次试跑时自动更新，不需要手动跑 `calibrate`。

之后看三个数：工具调用次数、Edit 次数、改-跑-改循环。轮数不到 100 时，对照合同里的改动处和陷阱，看模型是漏改了哪些位置，还是根本没有跑到陷阱，再决定下一题怎么改。

## 8. 文风检查

```bash
python scripts/check_prompt_style.py --prompt /绝对路径/PROMPT.md
```

`errors` 非空即非零退出，改完再预检；`warnings` 只作提示。检查项：

- 超过 240 字；Markdown 列表、标题、反引号；
- 顿号列举超过 3 项，或出现超过 1 处；
- “希望”出现超过 1 次；
- 规格腔和宣传腔词表（明确区分、不受影响、可复核、平滑、干净关闭、互相串、一致性、确保、闭环等）；
- 多段题面的末段只剩“……不能/不要……”式约束；
- 驼峰或下划线标识符、文件名、函数调用写法。

脚本拦的是常见模式，通过了也要人工读一遍：念出来像不像同事在描述问题。
